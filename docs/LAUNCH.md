# Launch and feedback plan

The immediate goal is ten real installation reports, not a promised star count.
This repository is publicly visible but all rights are currently reserved.
Check permissions with the maintainer before representing it as free/open-source
software or distributing a modified build.

## Before a public launch

- Inspect the latest CI run and review any failure; do not replace the dynamic
  badge with a hard-coded passing result.
- Complete the manual YouTube and physical shortcut checks for every desktop
  advertised as verified. Publish partial results honestly.
- Keep the README demo labeled as a replay of synthetic media-test output.
  Replace or supplement it with a real desktop recording only after that test
  has actually been performed; remove private links and account information.
- Publish clear release notes, install commands, dependency requirements,
  permission details, and known limits. Avoid claims of a standalone installer.
- Set `assets/social-preview.png` as the repository's social preview in
  Settings → General → Social preview → Edit → Upload an image.

## Reach the first testers

Pick one relevant Python/automation community and one desktop-productivity
community. Check each community's current self-promotion rules first. Share
the specific workflow, link the actual demo, disclose that you maintain VYBE,
and request installation feedback on a specific operating system. Do not
mass-post the same announcement or request stars in unrelated issues.

Lead with what is verified. At the current stage: a local MP4/MP3 pipeline with
real synthetic-media tests, plus a desktop shortcut integration that needs
hands-on reports. Explain that the source is rights-reserved.

## Track useful outcomes

Review the repository's Insights → Traffic when available, release downloads,
new installation reports, reproducible bugs, and successful repeat usage.
Record counts and dates without copying private user data into this repository.
Use feedback to reduce setup friction before a second announcement.

## Follow through

Respond to issues with an actionable next step, fix reproducible problems,
and publish release notes that explain the resulting behavior. Share an update
when a real improvement is available. Keep platform verification records and
license information current.
